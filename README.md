# work-schedule-core

하루 근무표에 신규 활동이나 휴가가 들어올 때, 기존 활동 구간을 나누고 다시 구성하는 Java 예제입니다.

콜센터 상담사 근무관리(WFM) 시스템을 개발하며 다룬 근무표 편집 규칙을 일반화해, 가상 데이터로 새로 구현했습니다. 회사의 실제 소스, 데이터, 설정은 포함하지 않습니다.

## 무엇을 하는가

### 1. 활동 추가에 따른 구간 재구성

09:00~18:00 상담에 12:00~13:00 점심을 넣고, 이어서 11:30~12:30 회의를 넣으면 다음과 같이 바뀝니다.

| 단계 | 결과 |
| --- | --- |
| 기본 근무 | 09:00-18:00 상담 |
| 점심 추가 | 09:00-12:00 상담 / 12:00-13:00 점심 / 13:00-18:00 상담 |
| 회의 추가 | 09:00-11:30 상담 / 11:30-12:30 회의 / 12:30-13:00 점심 / 13:00-18:00 상담 |

회의는 상담과 점심 두 활동에 걸쳐 들어왔고, 각 활동에서 회의와 겹치지 않는 시간만 남았습니다.

빈 시간이나 기본 근무 밖에 넣은 활동은 신규 구간이 되고, 자정을 넘는 야간 근무도 같은 방식으로 처리합니다.

| 입력 | 결과 |
| --- | --- |
| 위 근무표에 연장근무 18:00~19:00 | 기존 구간은 그대로, 18:00-19:00 연장근무 추가 |
| 야간 상담 22:00~익일 07:00에 휴게 익일 02:00~03:00 | 22:00-익일 02:00 상담 / 익일 02:00-익일 03:00 휴게 / 익일 03:00-익일 07:00 상담 |

### 2. 휴가 반영

소정근로 8시간 근무표(점심 12:00~13:00)에 휴가가 들어오면 다음과 같이 바뀝니다.

| 휴가 | 결과 |
| --- | --- |
| 오전반차 | 09:00-12:00 휴가 / 12:00-13:00 점심 / 13:00-14:00 휴가 / 14:00-18:00 상담 |
| 오전반차 + 오후반반차 | 09:00-12:00 휴가 / 12:00-13:00 점심 / 13:00-14:00 휴가 / 14:00-16:00 상담 / 16:00-18:00 휴가 |
| 오전반차 + 오후반차 | 09:00-18:00 휴가 (합계가 소정근로시간 이상이므로 종일휴가) |

## 처리 규칙

### 실무에서 다룬 규칙

- 신규 활동이 차지한 시간은 신규 활동으로 바꾸고, 기존 활동의 앞뒤 남은 시간은 원래 활동으로 보존한다.
- 신규 활동과 겹치는 기존 구간은 겹친 방식에 따라 정리한다. 신규 범위를 감싸면 앞은 줄이고 뒤는 새로 등록하고, 앞이나 뒤만 걸치면 걸친 쪽만 잘라내며, 완전히 덮이면 없앤다.
- 시간을 넓혀 넣은 활동은 그 범위 안의 기존 구간을 모두 정리한다.
- 같은 시작 시각의 구간은 하나만 존재한다. 시작 시각이 같은 활동이 들어오면 기존 활동을 대체하고, 뒤쪽 남은 시간은 원래 활동으로 남긴다.
- 빈 시간이나 기본 근무 밖에 넣은 활동은 신규 구간으로 추가한다. 연장근무가 여기에 해당한다.
- 원래 활동과 같은 활동을 그 자리에 다시 넣으면 "동일한 근무활동입니다."로 막는다.
- 근무표 중간에 빈 시간이 있을 수 있고, 그 빈 시간은 건드리지 않는다.
- 자정을 넘는 야간 근무는 시각이 아니라 날짜를 포함한 일시로 정렬하고 비교한다. 시각만으로 정렬하면 04:00이 18:00보다 앞에 와서 순서가 뒤집힌다.
- 하루 휴가 시간 합계가 소정근로시간 이상이면 종일휴가로 보고, 근무 시작부터 종료까지를 휴가 한 건으로 처리한다. 오전 휴가와 오후 휴가 사이에 점심이 끼어 시간이 이어지지 않아도 합계로만 판단한다.
- 반차 시간은 주간 8시간 근무는 4시간이다. 철야조처럼 소정근로시간이 다른 근무는 그 절반을 오전반차는 30분 단위 내림, 오후반차는 30분 단위 올림으로 맞춘다. 예: 10.5시간 철야조는 오전반차 5시간, 오후반차 5.5시간.
- 반반차는 2시간으로 고정한다.

### 이 예제에서 정한 규칙

- 시간 구간은 반개방 구간 `[시작, 종료)`로 다룬다. 경계만 맞닿는 활동은 겹치지 않는 것으로 보고 자르지 않는다.
- 시작과 종료가 같거나 거꾸로 된 활동은 만들 수 없다.
- 휴가는 근무시간으로 계산하는 활동에서만 차감하고, 점심 같은 휴게 구간은 그대로 둔다.
- 시간 단위 제한은 두지 않는다(분 단위). 실무 화면은 30분 칸으로 보여주지만, 저장되는 구간은 10분 단위처럼 더 짧을 수 있다.
- 이웃한 같은 이름의 활동을 하나로 합치지 않는다.
- 입력 리스트는 바꾸지 않고, 결과를 새 리스트로 돌려준다.
- 다음 날 시각은 `익일 02:00`처럼 표기한다.

### 실무에는 있었지만 이 예제에서 다루지 않는 것

- 근무일 마감 여부 확인
- 변경 전 구간의 이력 저장
- DB 저장과 트랜잭션 롤백, 여러 사용자의 동시 수정

## 구조

```text
src/main/java/io/github/jsleeio/schedule/
  Activity.java          활동 구간 하나 (이름, 시작, 종료, 근무시간 여부)
  ScheduleEditor.java    신규 활동 반영 및 구간 재구성
  VacationType.java      휴가 종류와 차감 시간 계산
  VacationPlanner.java   휴가 반영 (종일 판정, 차감 방향, 휴게 건너뛰기)
  Example.java           위 예시를 실행해 출력
src/test/java/io/github/jsleeio/schedule/
  ScheduleEditorTest.java
  VacationPlannerTest.java
```

`VacationPlanner`는 차감할 휴가 구간만 계산하고, 실제 구간 분할은 `ScheduleEditor`에 맡깁니다. 설계에 대한 설명은 [docs/design.md](docs/design.md)에 있습니다.

## 실행 방법

필요 환경: JDK 17 이상, Maven 3.8 이상

```bash
# 테스트 실행
mvn test

# 예제 실행
mvn -q compile
java -cp target/classes io.github.jsleeio.schedule.Example
```

IDE(Eclipse, IntelliJ)에서는 Maven 프로젝트로 가져온 뒤 `Example`의 `main`을 실행하면 됩니다.

저장소에 코드가 올라가면 GitHub Actions가 JDK 17 환경에서 `mvn test`를 실행합니다. 결과는 저장소의 Actions 탭에서 확인할 수 있습니다.

## 테스트

테스트 이름이 곧 처리 규칙이 되도록 작성했습니다. JDK 17, JUnit 5.10.1 기준 25개 테스트가 모두 통과합니다.

**ScheduleEditorTest**

- 기본 구간 중간에 활동을 넣으면 앞뒤 시간이 원래 활동으로 남는다
- 여러 활동에 걸친 신규 활동은 걸친 활동을 각각 잘라낸다
- 시작 시각이 같으면 기존 활동을 대체하고 뒤쪽 남은 시간은 원래 활동으로 남는다
- 신규 활동이 기존 활동을 완전히 덮으면 기존 활동은 사라진다
- 시간을 넓혀 넣은 활동은 범위 안의 기존 구간을 모두 정리한다
- 경계만 맞닿는 활동은 잘리지 않는다
- 빈 근무표에 넣은 활동은 그대로 신규 구간이 된다
- 기본 근무 밖에 넣은 연장근무는 신규 구간으로 추가된다
- 근무표 중간의 빈 시간은 건드리지 않는다
- 자정을 넘는 야간 근무도 날짜 기준으로 순서가 유지된다
- 원래 활동과 같은 활동을 그 자리에 다시 넣으면 막는다
- 결과 근무표는 빈틈이나 겹침 없이 처음과 끝이 유지된다
- 입력한 근무표 리스트는 바뀌지 않는다
- 시작과 종료가 같거나 거꾸로면 활동을 만들 수 없다
- 겹치는 구간이 있는 근무표는 받지 않는다

**VacationPlannerTest**

- 오전반차는 근무 시작부터 차감하고 점심은 건너뛴다
- 오후반반차는 근무 종료 쪽에서 2시간을 차감한다
- 오전반차와 오후반반차가 함께 오면 사이의 근무는 남는다
- 오전반차와 오후반차는 시간이 이어지지 않아도 합계로 종일휴가가 된다
- 종일휴가는 근무 시작부터 종료까지 휴가 한 건이 된다
- 반차 시간은 주간 8시간이면 4시간, 철야조 10.5시간이면 오전 5시간과 오후 5.5시간이다
- 10.5시간 철야조의 오전반차는 근무 시작부터 5시간을 차감한다
- 10.5시간 철야조의 오후반차는 근무 종료 쪽에서 5.5시간을 차감한다
- 휴가 목록이 비었거나 소정근로시간이 0 이하면 막는다
- 차감할 근무시간이 부족하면 막는다

## 실무와 다른 점

| 구분 | 실무 | 이 예제 |
| --- | --- | --- |
| 기술 | Java, Spring Framework(전자정부프레임워크), MyBatis, Oracle, Nexacro N24 | Java 17, JUnit 5 |
| 저장 | 근무활동 행을 DB에서 수정, 삭제, 삽입하고, 변경 이력을 남기며, 오류 시 전체 롤백 | 메모리의 리스트로 계산만 수행 |
| 입력 | 30분 단위 시간표 화면에서 드래그앤드롭, 시간 변경 팝업 | 메서드 호출 |
| 코드 | 회사 소스 | 처음부터 새로 설계 (클래스 구조, 시간 표현 방식 모두 실무와 무관) |

## AI 활용

코드 초안 작성에 AI(Claude)를 활용했으며, 처리 규칙과 테스트 시나리오는 실무에서 다룬 근무표 규칙을 기준으로 정했습니다.
